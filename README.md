# Simon Karanja Coffee Exports — сайт компании

Многостраничный сайт на Next.js (App Router) для оптовых поставок кенийского
зелёного кофе (AA / AB / PB) обжарщикам и импортёрам России. Контент и
палитра — по фирменному баннеру: тёмно-зелёные высокогорья, латунный акцент,
пергаментный фон.

## Стек

Next.js 16 (App Router, React 19, TypeScript), Tailwind v4 для утилит +
обычный CSS для дизайн-токенов и инфографики (`app/globals.css`). Инфографика
— inline SVG/CSS-компоненты, без графических библиотек и без картинок.
Шрифты (Oswald / Literata / JetBrains Mono, с кириллицей) подключены через
`next/font/google` и самохостятся при сборке — сайт ни от чего внешнего не
зависит в рантайме.

## Разработка

```bash
npm install
npm run dev       # http://localhost:3000
npm run build     # прод-сборка, все страницы статические
npm run start     # прод-сервер после build
npm run lint
```

## Структура

```
app/
  layout.tsx        шрифты, метаданные, шапка/подвал
  page.tsx           Главная
  about/             О компании
  products/          Продукция — грейды AA/AB/PB, профиль чашки (каппинг)
  sourcing/          Снабжение — высота регионов, календарь урожая,
                      цепочка "от фермы до чашки", паспорт лота
  logistics/         Логистика — объёмы поставки, маршрут доставки, документы
  contact/           Контакты и форма запроса прайса
  sitemap.ts, robots.ts, icon.svg
components/          UI и инфографика (переиспользуются между страницами)
lib/data.ts          Весь контент и данные сайта — единый источник правды
lib/revealObserver.ts   лёгкий общий "reveal on scroll" на всю страницу
```

Меняя данные (высоты регионов, грейды, баллы каппинга, объёмы, контакты) —
правьте `lib/data.ts`, а не разметку страниц.

## Что нужно заменить перед публикацией

| Что | Где | Сейчас |
|---|---|---|
| Кенийский телефон | `lib/data.ts` → `company.phoneKe` | **заглушка** из баннера — подставьте реальный номер |
| Номер WhatsApp | `lib/data.ts` → `company.whatsapp` | российский номер из баннера |
| Данные сезона | `lib/data.ts` → `grades`, hero-блок на Главной | сезон 2025/26, ориентировочно |
| Баллы каппинга | `lib/data.ts` → `cupScores` | среднее по лотам AA, для примера |
| Паспорт лота | `lib/data.ts` → `lotPassport` | вымышленный лот `KE-25/NY-0147`, демонстрирует формат |
| Сроки морского плеча | `components/RouteMap.tsx` (подписи "МОРЕМ · …") | 25–32 / 35–45 дней, ориентировочно |
| Домен в метаданных | `app/layout.tsx`, `app/sitemap.ts`, `app/robots.ts` | `kenyacoffee.co.ke` |

## Заметки по реализации

- Светлая/тёмная тема — CSS-токены на `:root`, плюс переключатель
  (`components/ThemeToggle.tsx`), сохраняющий выбор в `localStorage`;
  инлайн-скрипт в `<head>` выставляет тему до первой отрисовки, чтобы не
  было мигания.
- "Появление при скролле" (`components/Reveal.tsx`) — один общий обработчик
  `scroll`/`resize` на всю страницу (`lib/revealObserver.ts`), а не
  `IntersectionObserver` на каждый блок: в проде на нескольких страницах
  наблюдался случай, когда часть из множества одновременно создаваемых
  `IntersectionObserver` с одинаковыми `threshold`/`rootMargin` не получала
  уведомлений о пересечении — блок так и оставался с `opacity:0`. Прямая
  проверка `getBoundingClientRect` работает предсказуемо.
- Формы не имеют бэкенда: кнопка «Отправить запрос» на `/contact` собирает
  `mailto:`, «Скопировать текст» кладёт заявку в буфер обмена.
- Все сетки на `1fr` явно используют `minmax(0, 1fr)` — «голый» `1fr` не
  сжимается ниже содержимого и может распереть контейнер на мобильных
  экранах с длинным несворачиваемым текстом (наступили на это в `.tier` и
  `.two-col`).
